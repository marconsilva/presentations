Enter: Spec-Driven Development

Spec-Driven Development

Define the contract first

What is Spec-Driven Development?

  • Write the specification before writing code
  • The spec becomes the single source of truth
  • Agents use the spec as ground truth for generation
  • Humans review specs; agents implement them

Types of Specifications

📄

OpenAPI

REST contracts, schemas, endpoints

🏗️

Architecture Docs

System design, component boundaries, data flow

📋

Requirements

User stories, acceptance criteria, constraints

Spec as Ground Truth

  • Agents read the spec on every invocation
  • Generated code stays aligned with design intent
  • Drift is caught via spec validation
  • Specs evolve — agents adapt

Why Spec-First?

🎯 Precision

Agents generate exactly what the spec describes — no hallucinations

🔄 Repeatability

Same spec → same output, every time

👥 Collaboration

Teams align on specs before a single line is written

📈 Scalability

Multiple agents work in parallel from the same contract

Spec2Cloud

From specification to deployment

The Spec2Cloud Pipeline

1 Write your spec (OpenAPI, architecture doc, requirements)
2 Copilot agent generates implementation from spec
3 Automated validation against the spec contract
4 CI/CD pipeline packages and deploys to cloud
5 Runtime verification confirms spec compliance

Spec2Cloud Flow

Example: OpenAPI Spec

spec/openapi.yaml
openapi: 3.0.3
info:
  title: Order Service API
  version: 1.0.0
paths:
  /orders:
    post:
      summary: Create a new order
      requestBody:
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/Order'
      responses:
        '201':
          description: Order created

Agent Reads the Spec

.github/copilot-instructions.md
# Copilot Instructions

## API Implementation
- Always read spec/openapi.yaml before generating endpoints
- Validate request/response schemas against spec
- Generate tests that verify spec compliance
- Never add endpoints not defined in the spec

Squads

Multi-Agent Development

What are Squads?

Multiple specialized AI agents working together on a single codebase

  • Created by Brady Gaster (Microsoft)
  • MIT Licensed — open source
  • Install: npm install @anthropic/squads
  • Config lives in .squad/ directory

Squad Roles

🎨

Designer

Creates UI specs, component hierarchy, accessibility guidelines

💻

Coder

Implements features from specs, follows conventions, writes clean code

🔍

Reviewer

Reviews PRs, checks spec compliance, ensures quality standards

🧪

Tester

Generates test cases from spec, runs validation, reports coverage

Squad Configuration

.squad/ directory
your-repo/
├── .squad/
│   ├── config.yaml        # Squad orchestration config
│   ├── designer.md        # Designer agent instructions
│   ├── coder.md           # Coder agent instructions
│   ├── reviewer.md        # Reviewer agent instructions
│   └── tester.md          # Tester agent instructions
├── spec/
│   └── openapi.yaml       # The source of truth
└── src/                   # Generated & maintained code

Squad Workflow

How Squads Communicate

  • Agents communicate via spec artifacts — not chat
  • Each agent has a scoped role and clear boundaries
  • Handoffs happen through file changes + PR reviews
  • Human stays in the loop at spec-review checkpoints

Traditional vs Spec-Driven + Squads

Aspect Traditional Spec + Squads
Planning Meetings → tickets Write a spec
Implementation Manual coding Agent generates from spec
Code Review Human reviewers Reviewer agent + human approval
Testing Write tests after code Tester agent from spec
Consistency Varies by developer Spec-enforced uniformity

Demo: What We'll Build

A new REST API endpoint — from spec to deployed, using Squads

1 Define endpoint in OpenAPI spec
2 Squad designer creates interface contract
3 Squad coder implements the endpoint
4 Squad tester generates integration tests
5 Squad reviewer validates spec compliance → merge

Step 1: Write the Spec

paths:
  /products/{id}/reviews:
    get:
      summary: Get product reviews
      parameters:
        - name: id
          in: path
          required: true
          schema:
            type: string
      responses:
        '200':
          description: List of reviews
          content:
            application/json:
              schema:
                type: array
                items:
                  $ref: '#/components/schemas/Review'

Step 3: Coder Agent Output

// Generated by Squad Coder Agent
app.get('/products/:id/reviews', async (req, res) => {
  const { id } = req.params;
  
  const reviews = await reviewService.getByProductId(id);
  
  if (!reviews) {
    return res.status(404).json({ 
      error: 'Product not found' 
    });
  }
  
  res.json(reviews);
});

✓ Matches spec schema · ✓ Error handling included · ✓ Typed responses

Step 4: Tester Agent Output

describe('GET /products/:id/reviews', () => {
  it('returns reviews for valid product', async () => {
    const res = await request(app)
      .get('/products/prod-123/reviews');
    
    expect(res.status).toBe(200);
    expect(res.body).toBeInstanceOf(Array);
    expect(res.body[0]).toHaveProperty('rating');
  });

  it('returns 404 for unknown product', async () => {
    const res = await request(app)
      .get('/products/unknown/reviews');
    expect(res.status).toBe(404);
  });
});
