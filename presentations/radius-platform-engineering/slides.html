Introducing Radius

A unified application model for cloud-native development

What is Radius?

  • Open-source platform by Microsoft (radapp.io)
  • Unified application model across any cloud
  • Separates what developers need from how it is provisioned
  • Built on Kubernetes, integrates with existing IaC tools

Core Concepts

Applications, Environments, Recipes, Connections

The Application Model

Environments

An Environment is a landing zone where applications are deployed.

Dev

Local containers, lightweight DBs

Staging

Shared cloud resources, cost-optimized

Production

HA, geo-replicated, fully governed

Same app definition, different infrastructure per environment

Connections

Automatic dependency injection from infrastructure to containers.

// Radius injects connection info as env vars
REDIS_HOST=redis-abc.cache.windows.net
REDIS_PORT=6380
REDIS_PASSWORD=********
SQL_CONNECTION_STRING=Server=...

No secrets in code. No manual wiring. Automatic.

Recipes: The Bridge

Recipe = A template that fulfills a portable resource type using real infrastructure (Terraform module, Bicep template, etc.)
  • Platform engineers author recipes
  • Developers consume them transparently
  • Same resource type, different recipe per environment

Defining an Application

// app.bicep
resource app 'Applications.Core/applications@2023-10-01-preview' = {
  name: 'myapp'
}

resource frontend 'Applications.Core/containers@2023-10-01-preview' = {
  name: 'frontend'
  properties: {
    application: app.id
    container: { image: 'myregistry/frontend:latest' }
    connections: { redis: { source: cache.id } }
  }
}

resource cache 'Applications.Datastores/redisCaches@2023-10-01-preview' = {
  name: 'cache'
  properties: { application: app.id }
}

Platform Engineers Create Recipes

  • Define how each resource type is provisioned
  • Encode compliance, security, cost controls
  • Register recipes to environments
  • Developers never touch infrastructure directly
Think of it as an internal developer platform with a well-defined API contract.

Recipe Types

Terraform Recipes

Point to any Terraform module in a registry. Radius executes it, manages state, and wires outputs to connections.

Bicep Recipes

Use Bicep templates stored in OCI registries. Native Azure integration with ARM deployment.

Terraform Recipe Example

# main.tf - Redis recipe for production
resource "azurerm_redis_cache" "this" {
  name = var.name
  location = var.location
  resource_group_name = var.resource_group
  capacity = 2
  family = "C"
  sku_name = "Standard"
  minimum_tls_version = "1.2" # Security guardrail
}

output "result" {
  value = {
    host = azurerm_redis_cache.this.hostname
    port = azurerm_redis_cache.this.ssl_port
    password = azurerm_redis_cache.this.primary_access_key
  }
}

Registering Recipes to Environments

// environment.bicep
resource env 'Applications.Core/environments@2023-10-01-preview' = {
  name: 'production'
  properties: {
    compute: { kind: 'kubernetes', ... }
    recipes: {
      'Applications.Datastores/redisCaches': {
        default: {
          templateKind: 'terraform'
          templatePath: 'registry.example.com/recipes/redis:1.0'
        }
      }
    }
  }
}

Architecture Deep Dive

How Radius works under the hood

Radius Architecture

Kubernetes-Native

  • Installs into any conformant K8s cluster
  • UCP runs as a set of controllers and resource providers
  • Containers deploy as standard K8s Deployments and Services
  • Works alongside existing Helm charts, Kustomize, GitOps

Multi-Cloud Portability

Resource Type Azure Recipe AWS Recipe
Redis Cache Azure Cache for Redis ElastiCache
SQL Database Azure SQL RDS PostgreSQL
Message Queue Azure Service Bus Amazon SQS
Object Storage Azure Blob S3

Same app definition, different cloud, different recipe, same result

Tooling and Dashboard

CLI, Dashboard, and CI/CD integration

The rad CLI

# Initialize Radius in a cluster
$ rad install kubernetes

# Create an environment
$ rad env create production --namespace prod

# Deploy an application
$ rad deploy app.bicep --environment production

# Check app status
$ rad app status myapp

# View application graph
$ rad app graph myapp

Getting Started

# 1. Install the rad CLI
$ curl -fsSL https://get.radapp.dev/tools/rad/install.sh | bash

# 2. Initialize Radius on your cluster
