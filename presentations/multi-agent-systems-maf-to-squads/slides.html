Microsoft Agent Framework

Structured orchestration at enterprise scale

What is MAF?

  • Open-source framework for building multi-agent AI systems
  • Runtime for agent lifecycle, execution, messaging, and state
  • First-class .NET support with an extensible architecture
  • Built-in patterns for communication and orchestration
  • Production-ready primitives: tools, memory, and policies

MAF Core Concepts

Agents

Autonomous units with identity, instructions, and tools

Runtime

Manages agent lifecycle, execution, and communication

Channels

Typed message buses connecting agents

Teams

Logical groups of agents working toward a shared goal

Agent Roles

🧠 Planner

Decomposes goals into sub-tasks

🔧 Worker

Executes domain-specific actions

🔍 Critic

Validates outputs & enforces quality

📡 Router

Directs messages to appropriate agents

🗄️ Memory

Shared state & context persistence

Communication Channels

  • Direct — point-to-point messaging
  • Broadcast — one-to-many fan-out
  • Topic-based — pub/sub filtering
  • Request-Reply — synchronous ask/answer

Orchestration Patterns

How agents coordinate their work

Sequential (Pipeline)

Best for: deterministic workflows with clear dependencies

Parallel (Fan-out / Fan-in)

Best for: independent sub-tasks that can run concurrently

Event-Driven (Reactive)

Best for: monitoring, incident response, autonomous systems

MAF in Code — Runtime + State

// Configure an agent runtime
builder.AddAgent("planner")
    .WithRole("Break work into steps")
    .WithTools(searchTool, repoTool)
    .WithMemory(new VectorMemory(embeddingService))
    .WithState(new RedisStateStore(redis));

builder.AddWorkflow("research-pipeline")
    .Sequential("planner", "researcher", "reviewer")
    .WithCheckpointing(TimeSpan.FromMinutes(5));

The key idea: runtime, memory, state, and orchestration are explicit — not hidden in prompts.

The Squads Paradigm

Composable, GitHub-native agent teams

What are Squads?

  • Created by Brady Gaster at Microsoft
  • Licensed under MIT
  • Squad-based workflows: composable agent teams
  • Configuration lives in a .squad/ directory
  • GitHub-native: integrates with Copilot & repos

Three Commands to a Squad

$ npm i -g @bradygaster/squad-cli
$ squad init
$ copilot --agent squad

The .squad/ Directory

.squad/
├── squad.config.ts      # SDK-first TypeScript config
├── agents/
│   ├── researcher.ts    # Agent definitions
│   ├── coder.ts
│   └── reviewer.ts
├── workflows/
│   └── code-review.ts   # Workflow compositions
└── memory/
    └── shared.json      # Persistent squad memory

SDK-First Configuration

// .squad/squad.config.ts
const squad = {
  name: 'code-review-squad',
  routing: ['named', 'domain', 'skill-aware'],
  agents: [
    { name: 'researcher', domain: 'documentation', skills: ['search', 'summarize'] },
    { name: 'coder', domain: 'implementation', skills: ['write', 'refactor', 'test'] },
    { name: 'reviewer', domain: 'quality', skills: ['review', 'security-scan'] }
  ]
};

export default squad;

Routing Strategies

Reviewer Lockout

The Rule

An agent that produced output can never be routed as its own reviewer

Why It Matters

Prevents self-validation bias — ensures independent quality checks

This is enforced at the runtime level, not by convention — it cannot be bypassed by prompt injection.

When to Use What?

Dimension MAF Squads
Configuration Code-defined (Python/.NET) TypeScript SDK-first
Runtime Self-hosted / Azure GitHub Copilot native
Best for Research & custom topologies Developer workflows & CI/CD
Governance Build your own Built-in audit & approval
Memory Pluggable providers Persistent squad memory

Decision Framework

  • MAF when you need full control over agent runtime & topology
  • MAF when integrating with Azure AI services deeply
  • Squads when your workflow is GitHub-centric
  • Squads when you want fast setup with governance built-in
  • Both can coexist in one delivery flow — runtime agents plus repo-native squads
