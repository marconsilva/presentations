The Core Premise

Platform engineering creates golden paths so developers can ship outcomes instead of stitching infrastructure together.

Now the platform's users are not only humans. They are increasingly autonomous systems.

Platform Engineering Principles

1

Platform as product

Designed for usability, feedback loops, and adoption.

2

Golden paths

3

Self-service

Provision what teams need without tickets or tribal knowledge.

Why the Stakes Changed

When software creation speeds up 10x with AI, infrastructure friction becomes the next bottleneck.

The value of the platform is now measured by how quickly both people and agents can move through it safely.

AI Agents Are Platform Consumers

  • They request environments, databases, queues, and model-serving endpoints.
  • They build and deploy application changes through APIs and CLIs.
  • They need clear contracts, predictable responses, and machine-readable guardrails.

What Agents Need From Platforms

Predictability

Stable APIs, typed resources, deterministic workflows, explicit state.

Safety

Policy-aware actions, bounded permissions, approvals, rollback paths.

Context

Discoverable catalogs, environment metadata, dependency graphs, events.

Abstraction

Request a capability like cache or model endpoint, not 40 cloud knobs.

Why Radius Matters

Open-source cloud-native platform primitives that map well to both developers and agents

Radius in One Sentence

That is exactly the contract platform engineering wants: application intent on one side, governed implementation on the other.

Radius Core Concepts

Applications

Logical application boundary containing containers and resources.

Environments

Landing zones that define where and how workloads are realized.

Recipes

Templates that fulfill resource intent using concrete infrastructure.

Connections

Bindings that inject infrastructure details back into applications.

The Radius Mental Model

Recipes Encode the Golden Path

  • Platform engineers author recipes with Terraform, Bicep, or other infrastructure templates.
  • Recipes embed security, cost, topology, and compliance decisions once.
  • Developers and agents consume the resource type, not the cloud-specific implementation.
resource redis 'Applications.Datastores/redisCaches@2023-10-01-preview' = { name: 'cache' properties: { application: app.id } } // Environment decides recipe: // dev -> local container // prod -> managed cloud cache

Environments Make Intent Portable

Dev

Fast loops, local services, low cost.

Stage

Shared infrastructure, realistic integration paths.

Prod

HA, observability, policy, enterprise guardrails.

Same application definition. Different environment-level fulfillment. That is a superpower for automation.

Applications Give Agents a Cohesive Unit

Instead of scattering infra concerns across scripts, Radius gives the agent a single application object to reason over.

  • What components exist?
  • What resources are required?
  • What is connected to what?

Connections Eliminate Manual Wiring

Connections turn infrastructure into consumable application context.

CONNECTIONS: cache: host: prod-cache.internal port: 6380 authRef: secret://cache/password modelStore: endpoint: https://models.internal/api tokenRef: secret://models/token

For agents, that means fewer brittle assumptions, fewer hidden steps, and less secret sprawl.

Agents Interacting with Platform APIs

Good platform APIs let agents reason in capabilities, not implementation trivia.

Reference Flow: Agent to Deployment

  1. Interpret the user goal.
  2. Discover available environments and approved resource types.
  3. Generate or update the app definition.
  4. Deploy through Radius and observe state.
  5. Report results with evidence and rollback options.
User prompt: "Create a retrieval app with an API, a vector store, and staging deployment" Agent plan: - choose staging env - add containers - request datastore recipe - connect resources - run deployment - verify health

Self-Service for AI Workloads

AI apps need the same platform discipline as any other cloud-native system, plus a few more capabilities

Self-Service Infrastructure for AI Workloads

Serving

Model endpoints, inference containers, GPU-aware runtimes.

State

Vector stores, caches, databases, queues, artifact storage.

Operations

Identity, secrets, observability, cost controls, scaling policy.

AI changes the resource mix, but the platform pattern stays the same: intent, policy, automation, feedback.

Agent-Friendly Platform Abstractions

Capability-based

Ask for vector search, eventing, or model serving as platform capabilities.

Composable

Combine containers, resources, and connections into repeatable application patterns.

Inspectable

Expose status, outputs, health, events, and deployment history for reasoning loops.

Portable

Keep app definitions stable while environments swap actual infrastructure.

Intelligent Platform Capabilities

  • Recommendation — suggest the right recipe or environment for a workload shape.
  • Policy reasoning — explain why a deployment is blocked and what valid alternatives exist.
  • Optimization — tune cost, resilience, or performance based on observed usage.
  • Autonomous remediation — restart, scale, rotate, or roll back within bounded guardrails.

What the Platform Must Expose

  • Catalog of supported patterns and approved resources
  • Environment metadata and placement constraints
  • Execution state, events, health, and deployment history
  • Policy results that are understandable by both humans and agents

Guardrails Matter More, Not Less

Bad platform pattern

Give the agent broad cloud credentials and hope the prompt is good.

Better platform pattern

Give the agent a constrained platform contract with recipes, environments, and approval boundaries.

The platform is the safety layer between intelligent intent and expensive infrastructure actions.

Operating Model for Platform Teams

Design products

Publish application patterns, APIs, recipes, and example blueprints.

Instrument everything

Expose state and events so humans and agents can verify outcomes.

Close the loop

Use platform telemetry to refine defaults, policies, and automation.

In other words: build a platform that is usable by developers today and operable by agents tomorrow.
