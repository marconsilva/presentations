What is a Coding Agent?

A coding agent is an AI system that autonomously performs software engineering tasks.

  • It plans the work before writing code
  • It executes multi-step implementations
  • It reviews its own output and iterates
  • It ships code through PRs and CI/CD

Autocomplete vs. Agent

Dimension Copilot (Autocomplete) Coding Agent
Scope Single line / block Entire feature / system
Initiative Reactive (waits for you) Proactive (plans & acts)
Context Current file Full repository + tools
Output Code suggestion PR with tests & docs
Loop Single-shot Plan → Act → Review → Iterate

The Limitation of a Single Agent

One agent can do a lot. But real engineering isn't a solo sport.

  • Who reviews the agent's code?
  • Who writes the tests?
  • Who handles the architecture decisions?
  • Who ensures quality gates are met?

You need a team. An agent team.

Squad transforms a single AI into an always-on engineering crew with structured agentic ceremonies.

Squad Architecture

Agentic Ceremonies

Just like human teams, agent teams follow structured workflows:

1️⃣

Sprint Planning

Orchestrator breaks spec into tasks, assigns to agents

2️⃣

Parallel Execution

Multiple agents work simultaneously on different branches

3️⃣

Code Review

Reviewer agent evaluates PRs, requests changes if needed

4️⃣

Merge & Deploy

Quality gates pass → auto-merge → CI/CD deploys

Why Multi-Agent Beats Single-Agent

  • Specialization — each agent masters its domain
  • Parallelism — work happens concurrently
  • Checks & Balances — agents review each other
  • Scalability — add agents as the project grows
  • Resilience — one agent's failure doesn't block others
Demo: Squad Building Software from Scratch

Squad: Key Insights

  • Agents follow the same git workflow as humans
  • PRs, reviews, and CI/CD — not a separate system
  • Human oversight at merge gates — trust but verify
  • The team scales with the backlog, not headcount

Anatomy of a Good Specification

# Functional Specification: User Authentication Service

## Overview
A REST API service handling user registration, login,
and token management for the e-commerce platform.

## Functional Requirements
- Users can register with email + password
- JWT-based authentication with refresh tokens
- Rate limiting: 5 failed attempts → 15min lockout

## Technical Requirements
- Runtime: .NET 8 Minimal APIs
- Database: PostgreSQL with EF Core
- Deployment: Azure Container Apps
- Monitoring: Application Insights

## Acceptance Criteria
- All endpoints return proper HTTP status codes
- 99.9% uptime SLA
- Response time < 200ms p95

Trust & Governance

Agents at scale require guardrails:

  • Audit Trail — every agent action is logged in git history
  • Human-in-the-Loop — merge gates require human approval
  • Scope Boundaries — agents operate within defined repos/files
  • Quality Gates — CI must pass before any merge
  • Rollback — every change is a PR that can be reverted
