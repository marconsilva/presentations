What is Microsoft Agent Framework?

  • Open-source framework for building multi-agent AI systems
  • First-class .NET support with extensible architecture
  • Built-in patterns for agent communication and orchestration
  • Production-ready primitives: state, tools, memory

MAF Architecture

Anatomy of an Agent

  • Role — What it does
  • Capabilities — What it can do
  • Tools — How it acts on the world
  • Memory — What it remembers
  • Policies — What it must follow

Defining Agent Roles

var agent = new AgentBuilder()
    .WithName("ResearchAssistant")
    .WithRole("You are an expert researcher...")
    .WithCapabilities(Capability.WebSearch, Capability.Summarize)
    .WithTools(searchTool, summarizeTool)
    .Build();

Each role is a clear, bounded responsibility

Agent Communication

Channels & Protocols

Communication Channels

Message Protocols

  • Request/Response — Synchronous, typed contracts
  • Fire-and-Forget — Asynchronous event publishing
  • Streaming — Token-by-token for LLM outputs
  • Broadcast — Fan-out to all subscribed agents

Orchestration Patterns

Composing agent workflows

Sequential

Agents execute one after another in a defined pipeline

Best for: step-by-step workflows with clear input/output chains

Parallel

Multiple agents work simultaneously on independent subtasks

Best for: tasks that can be divided into independent units

Hierarchical Orchestration

Supervisors delegate, team leads coordinate, workers execute

Agent Memory & State

Short-term

Conversation context within a session

Long-term

Persisted knowledge across sessions

Shared

State accessible by multiple agents

State Management in MAF

// Configure agent state
builder.AddAgent("planner")
    .WithMemory(new VectorMemory(embeddingService))
    .WithState(new RedisStateStore(redis))
    .WithCheckpointing(interval: TimeSpan.FromMinutes(5));

State is injectable, testable, and backend-agnostic

Agent liveness and readiness probes

⚙️ Configuration

Centralized, environment-aware config

Aspire AppHost Configuration

var builder = DistributedApplication.CreateBuilder(args);

var redis = builder.AddRedis("state-store");
var ollama = builder.AddOllama("llm");

var research = builder.AddProject<ResearchAgent>("research")
    .WithReference(redis)
    .WithReference(ollama);

var analysis = builder.AddProject<AnalysisAgent>("analysis")
    .WithReference(redis)
    .WithReference(research);

builder.Build().Run();

Service Discovery for Agent Mesh

Using Service Discovery

// In Agent project - resolve other agents by name
builder.Services.AddHttpClient<IAgentClient>(client =>
{
    client.BaseAddress = new Uri("https+http://analysis");
});

// Aspire handles DNS resolution, load balancing, and retries

Zero config changes between local dev and production

Health Checks & Resilience

builder.Services.AddHealthChecks()
    .AddCheck<LlmHealthCheck>("llm-availability")
    .AddCheck<VectorStoreHealthCheck>("vector-store")
    .AddCheck<AgentReadinessCheck>("agent-ready");

// Aspire surfaces these in the dashboard
// Kubernetes uses them for pod scheduling

Unhealthy agents are automatically removed from the mesh

Resilience Patterns

🛠️ Retry

⚡ Circuit Breaker

Bound LLM call duration to prevent hangs

Production Best Practices

🔐 Security

  • Agent identity & auth
  • Least-privilege tool access
  • Prompt injection guards

📈 Scaling

  • Horizontal agent scaling
  • Rate limiting per agent
  • Queue-based load leveling

💰 Cost Control

  • Token budgets per request
  • Model routing (cheap vs capable)
  • Caching frequent queries

🛠️ Operations

  • Canary deployments
  • A/B testing agent prompts
  • Automated rollback
