Lab Setup & Prerequisites

Environment

Windows machine, Visual Studio or VS Code, .NET SDK, Git, and access to the sample repo.

AI Tooling

GitHub Copilot enabled, Copilot CLI agent mode available, and terminal access for guided prompts.

Mindset

Treat the agent as a modernization teammate: explore, propose, execute, verify, and review.

Success Criteria

By the end of the lab, participants have a migration plan, upgraded slices of the app, added tests, and a verified modernization workflow they can repeat.

Workshop Flow

We are not asking Copilot for one giant rewrite. We are building a controlled modernization loop.

Step 1

Codebase analysis with agent

Codebase Analysis with Copilot

  • Ask the agent to inventory projects, frameworks, packages, and architectural seams
  • Identify outdated dependencies, dead code, and areas with no tests
  • Summarize business-critical paths before touching implementation
Example agent prompt Analyze this legacy .NET solution for modernization. Summarize: - project structure and target frameworks - risky dependencies and coupling points - test coverage gaps - recommended first modernization slice

Human Review Rule

The agent accelerates discovery, but participants confirm findings against the actual solution structure and business context.

What a Good Analysis Produces

Structural Map

Projects, layers, shared utilities, and integration boundaries.

Hotspots

Files with high churn, high complexity, or broad dependency reach.

Constraints

Vendor SDKs, unsupported packages, old APIs, and deployment assumptions.

First Slice

A bounded area suitable for incremental modernization with low blast radius.

Exercise Checkpoint #1

Participants compare agent findings with the repo: Which modules are the safest first move, and which dependencies immediately constrain the migration path?

Step 2

Dependency mapping and risk assessment

Map Dependencies Before Refactoring

The agent helps surface hidden coupling, but the team decides which dependencies can be isolated, wrapped, or deferred.

Risk Assessment Matrix

Low Complexity / High Value

Controller cleanup, package updates, and extraction of DTO contracts.

High Complexity / High Value

Authentication flow, billing integrations, and schema-dependent services.

Low Complexity / Low Value

Cosmetic cleanup that does not reduce coupling or unlock migration.

High Complexity / Low Value

Large rewrites without test safety nets or measurable business gain.

Exercise Checkpoint #2

Teams tag each dependency as isolate now, wrap for later, or leave in place. The goal is to reduce blast radius before changing frameworks or runtime behavior.

Step 3

Migration strategy generation

Generate a Migration Strategy

Prompt the agent for a plan, not a rewrite Create a phased modernization strategy for this app. Include: - quick wins for week 1 - compatibility constraints - recommended extraction order - validation gates after each phase - rollback considerations
  • A strong strategy explains sequence, dependencies, and validation points
  • It aligns technical work with a bounded modernization slice
  • It keeps the team shipping while reducing long-term platform debt

Phased Roadmap

Phase 1 — Stabilize

Inventory packages, introduce adapters, document seams, and freeze risky areas behind tests.

Phase 2 — Extract

Move shared business rules and contracts into portable libraries with cleaner boundaries.

Phase 3 — Upgrade

Modernize selected projects, update dependencies, and refactor APIs incrementally.

Phase 4 — Validate & Expand

Run regression checks, capture learnings, and repeat the loop for the next modernization slice.

Step 4

Automated refactoring execution

Refactor with the Agent, Not Around It

  • Ask for bounded edits: one project, one seam, one architectural objective
  • Preserve behavior first, then improve readability, testability, and portability
  • Review generated diffs like production code, especially around legacy edge cases

Good Targets

Configuration wrappers, repository interfaces, service extraction, null-handling cleanup.

Watch Closely

Reflection, serialization, payment flows, date logic, and custom middleware behavior.

Example Refactoring Moves

Extract Service

Move business rules out of MVC controllers into focused application services.

Wrap Dependency

Introduce an adapter around a legacy SDK before replacing or upgrading it.

Separate Data Access

Reduce direct SQL calls in UI code and funnel access through stable interfaces.

Refactoring outcome Controller -> thin orchestration Service -> business rules Adapter -> external dependency boundary Tests -> describe expected behavior before and after migration

Exercise Checkpoint #3

Pause after the first automated refactor. Review the diff, identify any unexpected behavior changes, and decide whether the next change should be extraction, cleanup, or rollback.

Step 5

Test generation

Generate Tests to Create Safety

  • Start with characterization tests for fragile legacy behavior
  • Add focused unit tests around extracted services and adapters
  • Use agent-generated scenarios to cover happy path, edge path, and failure path
Example testing prompt Generate tests for the extracted order service. Cover: - valid order submission - invalid discount rules - downstream payment failure - behavior parity with the legacy controller

Step 6

Validation and verification

Validate Every Modernization Slice

Build Validation

Compile, restore, and confirm new boundaries do not break existing projects.

Behavior Validation

Run regression tests and compare outputs on key user journeys.

Operational Validation

Check logs, performance, startup assumptions, and environment-specific settings.

Verification Principle

Agent speed is only valuable when each loop ends with evidence: builds pass, tests pass, and the modernization slice still serves the business outcome.
