Prompt Engineering

Getting the best out of your AI collaborator

Prompt Engineering Best Practices

Be specific: describe inputs, outputs, constraints
Provide context: mention frameworks, patterns, conventions
Break complex tasks: one clear instruction at a time
Show examples: give a sample of expected output
Iterate: refine prompts based on results

❌ Weak Prompt

> Make a function to process orders

Vague, no context, no constraints

✅ Strong Prompt

> Create an async method in OrderService that validates stock, calculates total with tax, saves to EF Core, and returns OrderConfirmationDto. Use the repository pattern.

Specific, contextual, actionable

Custom Instructions

# .github/copilot-instructions.md

## Code Style
- Use C# 12 primary constructors
- Follow Clean Architecture layers
- Use MediatR for CQRS pattern

## Testing
- Use xUnit + FluentAssertions
- Arrange-Act-Assert pattern
- Mock with NSubstitute

## Naming
- Async suffix on async methods
- I-prefix on interfaces

Why Custom Instructions Matter

  • Team-wide consistency without code reviews for style
  • Version-controlled in your repository
  • Copilot reads them automatically on every prompt
  • Reduces "fix the AI's output" iterations by 60%+

Tests, Docs & Code Review

Copilot across the entire development lifecycle

Copilot for Tests

  • Generate unit tests from implementation
  • Edge cases & boundary conditions
  • Integration test scaffolding
  • Mutation testing suggestions
[Fact]
public async Task GetOrder_ValidId_ReturnsOrder()
{
    // Arrange
    var repo = Substitute.For<IOrderRepo>();
    repo.GetByIdAsync(1)
        .Returns(TestData.SampleOrder);
    var svc = new OrderService(repo);

    // Act
    var result = await svc.GetByIdAsync(1);

    // Assert
    result.Should().NotBeNull();
    result.Id.Should().Be(1);
}

Agent Mode

Autonomous multi-step tasks in your IDE

Agent Mode in Action

  • Reads, writes, and deletes files autonomously
  • Runs terminal commands (build, test, lint)
  • Self-corrects based on compiler errors
  • Chains multiple tools: search → edit → test → commit
  • Ask permission before destructive operations
💡 Pro tip: Use agent mode for scaffold + test + iterate workflows
